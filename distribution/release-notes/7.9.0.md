# 7.9.0

## Breaking Changes

### Plugins
- `javascript` with GraalVM: every execution of the script now runs in its own JavaScript context, which is closed afterwards. Objects created by the script, such as `{a: 1}` or the result of `JSON.parse()`, can no longer be used after the script has finished: storing one on the exchange, e.g. with `property.put('order', order)`, and reading it later in another plugin fails with `The Context is already closed`. Store it as a string instead: `property.put('order', JSON.stringify(order))`. Strings, numbers and Java objects such as `json`, `header` or `message` are not affected. An execution also takes longer than before, about 0.1 ms instead of 0.015 ms [#3625](https://github.com/membrane/api-gateway/issues/3625)

## Fixes

### Plugins
- `javascript` with GraalVM: a script whose last statement has no value, such as `var x = 1;`, no longer replaces the message body with `null`. A script that ends with a string now sets the body to that string, and a script that ends with a number or an array leaves the message unchanged, as with Rhino. Before, a string or a number failed with a `ClassCastException`, and an array set the body to `{}` [#3625](https://github.com/membrane/api-gateway/issues/3625)

## Security
- `javascript`: a script could see the values of an earlier request: the `json` body of an earlier request when the current one is not JSON, `param`/`params` and `response`/`statusCode` of an earlier exchange, and its own top-level variables, such as `var user`, set by an earlier request. With GraalVM, this also applied to scripts of other APIs. Every execution now only sees the values of its own exchange [#3625](https://github.com/membrane/api-gateway/issues/3625)
