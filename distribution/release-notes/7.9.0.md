# 7.9.0

## Security

- `rewriter`: redirects only go to the request's host or to the host written in `to`. Before, a crafted path could redirect to another host. Requests that would leave are answered with `400` [#3776](https://github.com/membrane/api-gateway/pull/3776)
- `json2Xml` and `xml2Json`: org.json 20260814 fixes CVE-2026-59171, slow parsing of numbers with very many digits [#3780](https://github.com/membrane/api-gateway/pull/3780)
- Start scripts, Docker images and the Windows service example start the JVM with `-XX:-UseBASE64Intrinsics` to mitigate CVE-2026-114938 ("Java4Shell"). Installing a fixed JDK is still necessary [#3814](https://github.com/membrane/api-gateway/pull/3814)

## New Features

### WSDL and SOAP
- `soap2Json` and `json2Soap`: convert between SOAP and JSON using a WSDL, e.g. to put a SOAP interface in front of a JSON backend or the other way round. See the tutorials in `wsdl-to-openapi` [#3757](https://github.com/membrane/api-gateway/pull/3757)

### Plugins
- `xml2Json` and `json2Xml`: `xmlSchema` maps with an XSD instead of heuristics, with typed values, arrays and element order from the schema. See `tutorials/xml` [#3757](https://github.com/membrane/api-gateway/pull/3757)
- `prometheus`: `jvm: true` exports JVM and process metrics with Micrometer names [#3751](https://github.com/membrane/api-gateway/pull/3751)
- `schedule`: call an `internal` API periodically, e.g. to refresh a token. See `tutorials/orchestration` [#3764](https://github.com/membrane/api-gateway/pull/3764)

### Kafka and JMS
- `jmsConsumer`: consume messages from a JMS queue or topic and run them through the API's flow. Needs the Membrane JMS Extension [#3802](https://github.com/membrane/api-gateway/pull/3802)
- `jmsProducer`: set header fields and properties of the message. Needs version 1.1.0 of the Membrane JMS Extension [#3802](https://github.com/membrane/api-gateway/pull/3802)

### AS2
- `as2Receiver` and `as2Sender`: receive and send AS2 messages with signed MDNs. Needs the Membrane AS2 Extension [#3762](https://github.com/membrane/api-gateway/pull/3762)

## Improvements

- `rateLimiter`: successful responses carry the `X-RateLimit-*` quota headers too [#3794](https://github.com/membrane/api-gateway/pull/3794)
- The default `backlog` of the `transport` is 500 instead of 50 [#3799](https://github.com/membrane/api-gateway/pull/3799)
- Clearer logs for failed TLS handshakes with clients and for unreachable backends [#3772](https://github.com/membrane/api-gateway/pull/3772) [#3735](https://github.com/membrane/api-gateway/pull/3735)
- In production, a request body that cannot be read, e.g. broken gzip, is logged at `info` with the log key that the problem details response contains, also in `openapi`. The `validator` no longer logs a stack trace for it [#3740](https://github.com/membrane/api-gateway/pull/3740)
- `kafkaConsumer` works with hot deployment, which is on by default. Before, it refused to start unless `hotDeploy` was turned off [#3802](https://github.com/membrane/api-gateway/pull/3802)
- New tutorials for Docker and rate limiting. Examples covered by tutorials were removed [#3792](https://github.com/membrane/api-gateway/pull/3792) [#3794](https://github.com/membrane/api-gateway/pull/3794) [#3793](https://github.com/membrane/api-gateway/pull/3793)

## Fixes

### Plugins
- `stompProxy`: accepts the `STOMP` frame and no longer sends an HTTP `500` before `CONNECTED` [#3768](https://github.com/membrane/api-gateway/pull/3768)
- `json2Xml`: invalid JSON in a request is answered with `400` instead of `500` [#3775](https://github.com/membrane/api-gateway/pull/3775)
- `xml2Json`: malformed XML in a request is answered with a client error that says the XML could not be converted, instead of `Internal server error.` [#3757](https://github.com/membrane/api-gateway/pull/3757)
- `balancerHealthMonitor`: checks run every `interval` (default 10 s) instead of always every 5 s [#3765](https://github.com/membrane/api-gateway/pull/3765)
- `limit`: keeps a `Content-Encoding` header it does not decode [#3787](https://github.com/membrane/api-gateway/pull/3787)
- `redisSessionManager`: reading a session extends it by `expiresAfterSeconds` [#3780](https://github.com/membrane/api-gateway/pull/3780)
- `llmGateway`: `maxOutputTokens` and `systemPrompt` apply to all field variants of Chat Completions, Responses and Gemini requests [#3746](https://github.com/membrane/api-gateway/pull/3746) [#3745](https://github.com/membrane/api-gateway/pull/3745)
- No more `Could not disable external XML access` warning with Saxon on the classpath [#3784](https://github.com/membrane/api-gateway/pull/3784)

### HTTP Transport and Runtime
- XOP/MTOM packages that cannot be reassembled and unparsable `Content-Type` headers are answered with `400` instead of `500` [#3738](https://github.com/membrane/api-gateway/pull/3738) [#3740](https://github.com/membrane/api-gateway/pull/3740)
- Request, status and header lines follow RFC 9112 line endings, and empty lines before a request are ignored. The default limit for these lines went up from 8092 to 8192 characters [#3798](https://github.com/membrane/api-gateway/pull/3798) [#3753](https://github.com/membrane/api-gateway/pull/3753)
- `Content-Encoding: x-gzip` is decoded like `gzip` [#3788](https://github.com/membrane/api-gateway/pull/3788)
- Target URLs with IPv6 literal hosts work, and IP addresses are no longer sent as SNI [#3805](https://github.com/membrane/api-gateway/pull/3805) [#3806](https://github.com/membrane/api-gateway/pull/3806)
- Malformed TLS ClientHellos no longer log an error with a stack trace [#3771](https://github.com/membrane/api-gateway/pull/3771)
- The client's `Proxy-Authorization` header is restored around calls through an outbound proxy [#3804](https://github.com/membrane/api-gateway/pull/3804)
- Exchange stores record request bodies the gateway did not read, and `limitedMemoryExchangeStore` counts them towards `maxSize` [#3797](https://github.com/membrane/api-gateway/pull/3797)
- Sending a message whose body was discarded fails. Before, the body was sent empty or cut short while the header could still announce the full length [#3797](https://github.com/membrane/api-gateway/pull/3797)
- Native memory no longer grows under heavy compressed traffic [#3732](https://github.com/membrane/api-gateway/pull/3732)

### HTTP/2
- A `host` field that differs from `:authority` is rejected [#3749](https://github.com/membrane/api-gateway/pull/3749)
- Exchange stores record streamed HTTP/2 bodies [#3796](https://github.com/membrane/api-gateway/pull/3796)
- Long-lived connections no longer keep every stream in memory [#3748](https://github.com/membrane/api-gateway/pull/3748)

## Breaking Changes

- `rewriter`: a redirect whose `to` has a group inside the host, e.g. `https://$1.example.com/`, answers every request with `400` [#3776](https://github.com/membrane/api-gateway/pull/3776)
- Reading a message body that was discarded, e.g. a request body the gateway did not need, fails like reading a streamed body. Before, it returned an empty or partial body. With `memoryExchangeStore`, the admin console shows an error for such a body instead of an empty one [#3797](https://github.com/membrane/api-gateway/pull/3797)
- `validator` with `wsdl`: SOAP faults are sent with `500`, or `400` for a SOAP 1.2 request, instead of `200` [#3766](https://github.com/membrane/api-gateway/pull/3766)
- `redis` with `ssl: true` checks the certificate's host name, and Sentinel setups now use TLS too [#3780](https://github.com/membrane/api-gateway/pull/3780)
- `rateLimiter` replaces `X-RateLimit-*` headers sent by the backend [#3794](https://github.com/membrane/api-gateway/pull/3794)
- Transfer codings other than `chunked` are rejected, and chunked bodies must follow RFC 9112 exactly [#3791](https://github.com/membrane/api-gateway/pull/3791) [#3797](https://github.com/membrane/api-gateway/pull/3797)
- Exchange stores with `bodyExceedingMaxSizeStrategy: ERROR` apply `maxBodySize` to HTTP/2 bodies too [#3796](https://github.com/membrane/api-gateway/pull/3796)
