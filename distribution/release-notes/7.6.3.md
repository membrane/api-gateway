# 7.6.3

## Breaking Changes
- Java API (only relevant when Membrane is used as a library): `MimeType.sortMimeTypeByQualityFactorAscending(String)` is renamed to `MimeType.sortMimeTypeByQualityFactorDescending(String)`. The old name described the opposite of what the method returns. Media types with equal quality factors now keep the order the client sent them in; before, they came out in reverse client order. Callers of the old name must switch to the new one [#3348](https://github.com/membrane/api-gateway/pull/3348)
- Java API (only relevant when subclassing `AbstractXMLSchemaValidator`): `validateAgainstSchemas` and `validateWith` no longer throw `InterruptedException`, `validateWith` takes a `ValidatorPool` instead of a `BlockingQueue`, and `init()` now calls `compileSchemas()` before creating validators [#3360](https://github.com/membrane/api-gateway/pull/3360)
- WSDL parsing: a binding's `type` is now resolved as a QName and must name a port type in the WSDL's `targetNamespace`. Before, only the local name was compared. A WSDL that writes the reference without a prefix (`type="MyPortType"`) while its default namespace is the WSDL namespace (`xmlns="http://schemas.xmlsoap.org/wsdl/"`) now fails at startup with `No portType found for binding`. This affects `soapProxy`, the WSDL `validator`, `webServiceExplorer` and `wsdl2openapi`. Fix the WSDL by prefixing the reference with the target namespace, e.g. `type="tns:MyPortType"`.
- Java API (only relevant when Membrane is used as a library): `Definitions.getOperations()`, `Definitions.findOperation(String)` and `Definitions.findBindingOperation(String)` are removed, because they mixed operations and bindings from every port type of the WSDL. Use `PortType.findOperation(String)` and `Binding.findBindingOperation(String)` on the port type or binding you mean. `Binding.getBindingOperation(String)` is replaced by `Binding.findBindingOperation(String)`, which returns an `Optional` instead of throwing.

## Improvements
- XML Schema, WSDL and Schematron validation no longer queue behind a fixed-size validator pool under load; schemas and the Schematron XSLT are compiled once at startup instead of once per pooled validator [#3360](https://github.com/membrane/api-gateway/pull/3360)


### wsdl2openapi
- An API now exposes a single port of a single service. A WSDL with several services needs the new `service` attribute. Before, the address of the first service was used. If a service's SOAP ports implement different port types, the new `port` attribute is required. Otherwise the SOAP 1.1 port is used, or the SOAP 1.2 port if there is no SOAP 1.1 port. To expose several services or ports, declare one API for each.
- Only the operations of the selected port's port type are exposed. Before, the operations of every port type in the WSDL were exposed. A WSDL without a service must now declare exactly one port type.
- Some problems in the WSDL are now reported at startup instead of on each request, and the whole API fails to start:
  - A `soapAction` that is not a URI. Percent-encode quotes, backslashes and spaces, or use `operations` to leave the operation out.
  - An error while reading the schema of an operation's request element. The request schema is now read once at startup, not on every request. Before, such an operation failed each request while the other operations kept working.

  An operation without an input message, or whose input message has no part or element, still starts and answers each request with an error.
- The SOAPAction header sent to a SOAP 1.1 service is now quoted (`SOAPAction: "urn:example:getCity"`), as SOAP 1.1 and the WS-I Basic Profile require. An operation without an action sends `SOAPAction: ""`. For SOAP 1.2, the action is sent as the `action` parameter of `Content-Type: application/soap+xml` instead of as a header. Any SOAPAction header the client sent is removed.
