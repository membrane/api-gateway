# 7.7.1

## Breaking Changes
- JSONPath conditions (`if`, `choose`/`case` and the API `test`): a filter, wildcard or deep-scan expression that matches nothing now evaluates to `false`. Before, its empty result list counted as `true`, so `test: $.animals[?(@.species == 'cat')]` was true for every document with an `animals` array, cat or not. A path that selects a property directly, such as `$.animals`, is still `true` when the property holds an empty array. A config that relied on an unmatched filter counting as `true` now takes the other branch [#3434](https://github.com/membrane/api-gateway/issues/3434)
- Request path normalization: before an API is selected, the path of the request is normalized as described in RFC 3986 6.2.2. Percent-encoded unreserved characters (letters, digits, `-`, `.`, `_`, `~`) are decoded, and the dot-segments `.` and `..` are resolved, also when they are percent-encoded. For example, `/a/../admin`, `/a/%2e%2e/admin` and `/%61dmin` all become `/admin`. The normalized path is used for routing, is what the flow sees (`request.uri`, `path` in expressions and scripts) and is sent to the backend. Before, only `/./` was removed for routing, and the path was forwarded as the client sent it. Reserved characters such as `%2F` and `%3B` stay encoded, and the query is not changed. The path as the client sent it is still available from `Exchange.getOriginalRelativeURI()` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Absolute-form requests: a request with an absolute URI in the request line (`GET http://example.com/admin HTTP/1.1`) is now routed by its path and passed on as `/admin`. Before, the absolute URI was compared with the paths of the APIs, so such a request usually matched a catch-all API. A forward proxy (`proxy`) still receives and forwards the absolute URI. An API without a target no longer forwards an absolute-form request to the host in the request line, so it cannot be used as an open forward proxy anymore [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Path parameters and duplicate slashes: path parameters (`;...`, for example `;jsessionid=1`) are now ignored and duplicate slashes are merged when the `path` of an API or an OpenAPI server base path is matched, as servlet containers and many web servers map requests that way. `/api;jsessionid=1/admin` and `/api//admin` are now routed to an API with `path: /api/admin`. The request is still forwarded unchanged. A configured `path` that itself contains `;` or `//` no longer matches. The parameters of a `path` with a URI template (`pathParam`) are taken from the path as it is matched: with `path: /products/{id}`, `/products//42` and `/products;x/42` give `id` `42`, and `/products/42;jsessionid=1` now gives `42` instead of `42;jsessionid=1`. The flow still sees the path as sent: `request.uri` and `path` in expressions and scripts, as well as the `rewriter`, see `;...` and `//`, so a `test:` expression like `path.startsWith('/api/admin')` does not match `/api;x/admin`. Use the `path` of an API, not a `test:` expression or a rewriter, to restrict access by path. APIs with an OpenAPI document answer `404` for now when `;...` or `//` appear in or before the server base path [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Path parameters that servlet containers resolve into another path are now rejected with `400 Bad Request` (problem type `invalid-path`), as Jakarta Servlet 6.0 (section 3.5.2) requires of a servlet container: a dot-segment with parameters, such as `/x/..;/admin` or `/x/.;/admin`, and an empty segment with parameters followed by another segment, such as `/;x/admin`. A trailing empty segment with parameters, as produced by servlet URL rewriting (`/app/;jsessionid=1`), is still accepted. Forward proxies (`proxy`) are not affected [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- A request path with a malformed percent-escape, that is a `%` not followed by two hex digits as in `/%zz/admin`, `/admin%` or `/%6%31dmin`, is now rejected with `400 Bad Request` (problem type `invalid-path`) before an API is selected. Decoding the characters around such an escape could otherwise create a new escape, e.g. `/%6%31dmin` would become `/%61dmin` and dodge an API with `path: /admin`. The same applies to an absolute-form request target that cannot be parsed, unless it goes to a forward proxy (`proxy`), which passes it on unchanged. Malformed escapes in the query are not checked, since the query is not decoded [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- A request target that is neither a path starting with `/` nor an absolute URI starting with `http://` or `https://`, such as `admin`, `./admin` or `x:/admin`, is now rejected with `400 Bad Request` (problem type `invalid-path`) before an API is selected. Such a target did not match the `path` of an API, so it usually went to a catch-all API, which still passed it on to the backend as `/admin`. `OPTIONS *` and, for a forward proxy (`proxy`), `CONNECT host:port` are still accepted, and `*` is accepted only with `OPTIONS` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- A `CONNECT` request is now rejected with `400 Bad Request` (problem type `invalid-path`) unless it is routed to a forward proxy (`proxy`). Before, an API without a target, or with a target `url` that has no path, answered it with `200` and opened a tunnel to the host and port in the request line. The tunnel could reach any host Membrane can reach, and the requests sent through it bypassed the flow of every API. A STOMP proxy (`stompProxy`) still accepts the `CONNECT` frame of STOMP [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- A backslash in the request path, such as `/api\admin`, is now rejected with `400 Bad Request` (problem type `invalid-path`), also in an absolute-form target. A backslash is not allowed in a URI, and some servers treat it like `/`, so routing, the flow and the backend could disagree about the path. RFC 9112 (section 3.2) advises rejecting such a request rather than correcting it, and servlet containers and Spring Security reject it by default. Before, the API was selected by the path with the backslash, and the backslash was forwarded as `%5C`. Clients have to send a backslash in the path as `%5C`, which is still accepted and forwarded unchanged. A backslash in the query is still accepted. Forward proxies (`proxy`) are not affected [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- XML messages that contain a DOCTYPE are now rejected with `400 Bad Request` by `transform`, `soap2Rest`, `rest2Soap` and a `validator` with a `schematron` file, in requests and in responses. API messages do not need a DTD, so these plugins no longer accept one. This also applies to the output of a stylesheet that declares `doctype-system` or `doctype-public` when it is passed on to another transformation, such as a second `transform` or the JSON conversion of `rest2Soap` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- The stylesheets of `transform`, `soap2Rest` and `rest2Soap`, and the documents they load with `document()`, can no longer use an external DTD or external entities. Such a stylesheet now fails to compile, for `transform` when the API starts and for `soap2Rest` and `rest2Soap` when it is first used, and loading such a document with `document()` makes the transformation fail. `xsl:include`, `xsl:import`, `document()` itself and internal entities, as in `<!DOCTYPE xsl:stylesheet [<!ENTITY nbsp "&#160;">]>`, still work [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Java API (only relevant when Membrane is used as a library): `URIUtil.normalizeSingleDot(String)` is removed. Use `URIUtil.normalizeRequestTarget(String)`, which also decodes percent-encoded unreserved characters and resolves `..` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Java API (only relevant when Membrane is used as a library): `XSLTTransformer.transform` now takes a `StreamSource` instead of any `Source`. Code compiled against 7.7.0 that calls it has to be recompiled, and code that passes a `DOMSource` or `SAXSource` has to pass a `StreamSource` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)

## Fixes
- A request path starting with `//` is now forwarded unchanged. Before, its first segment was taken as a host name and dropped, so `//x/admin` reached the backend as `/admin` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
