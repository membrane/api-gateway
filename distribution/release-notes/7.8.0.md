# 7.8.0

## Breaking Changes

### WebSockets
- WebSocket message size limit: when the `webSocket` plugin has frame interceptors (`wsLog`, `wsStompReassembler`, `wsInterceptor`), a message may now be at most 16 MiB, configurable with the new `maxMessageSize` attribute. A peer that sends a larger message, or announces a larger frame, is sent a close frame with status `1009` (message too big) and the connection is closed. Before, frames of any size were accepted and held in memory, so a single client could exhaust the gateway's memory. Without frame interceptors there is no limit, see below [#3478](https://github.com/membrane/api-gateway/pull/3478)
- WebSocket connections through a `webSocket` plugin without frame interceptors are now relayed byte for byte, without parsing WebSocket frames. Before, every frame was parsed and written anew, which held each frame in memory and closed the connection on frames it could not parse, such as a close frame without a status code [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Fragmented WebSocket messages are now joined when the `webSocket` plugin has frame interceptors: the interceptors and the receiving peer get each message as a single frame. Ping and pong frames between the fragments are passed on right away; a close frame in the middle of a message drops the incomplete message. Before, each fragment went through the interceptors on its own, so `wsStompReassembler` failed on the first fragment, dropped it and passed the rest on, and the receiver closed the connection with a protocol error. A continuation frame without a message to continue, or a new message before the previous one is complete, now closes the connection with status `1002` (protocol error) [#3478](https://github.com/membrane/api-gateway/pull/3478)
- WebSocket extensions are no longer negotiated when the `webSocket` plugin has frame interceptors: the `Sec-WebSocket-Extensions` header is removed from the upgrade request, so messages are not compressed with `permessage-deflate`. Frame interceptors could not read compressed messages, and RFC 6455 (section 5.4) does not allow joining fragments once an extension is in use. Configurations that removed the header themselves, for example with a `groovy` plugin, no longer need to. Without frame interceptors, extensions are negotiated as before [#3478](https://github.com/membrane/api-gateway/pull/3478)
- A failing WebSocket frame interceptor now closes the connection: both peers are sent a close frame with status `1011` (internal error), and the failure is logged at `ERROR`. Before, the message was dropped, the failure was logged, and the connection stayed open, so messages could get lost without either peer noticing. This also applies to `wsStompReassembler` when a text message is not a valid STOMP frame [#3478](https://github.com/membrane/api-gateway/pull/3478)
- WebSocket frame interceptors are now initialized once, when the API starts. An interceptor that fails to initialize stops the start with a configuration error. Before, the interceptors were initialized again for each new connection, while other connections were using them, and a failure was only logged. Custom interceptors (`wsInterceptor`) that relied on `init` being called per connection have to keep per-connection state elsewhere [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Upgraded connections (WebSocket, `Upgrade: tcp`), `CONNECT` tunnels of a forward proxy (`proxy`) and connections of a `stompClient` no longer time out on the backend side: once a connection is upgraded, the read timeout of the HTTP client (`connection.soTimeout`) no longer applies. Before, a connection on which the backend sent nothing for that long was closed, while the client side never timed out [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Admin API WebSocket (`/ws` of `adminApi`): an upgrade request without a `Sec-WebSocket-Key` header is now rejected with `400 Bad Request`. Ping frames are answered with a pong, and a close frame is answered with a close frame, after which the server closes the connection. Before, an upgrade without a key was accepted, and ping and close frames were ignored [#3478](https://github.com/membrane/api-gateway/pull/3478)

### Routing and URI Templates
- URI templates in OpenAPI paths and in the `path` of an `api` now match their fixed text as it is, as defined by OpenAPI path templating. Before, characters like `.`, `+`, `$`, `(`, `)` and `*` acted as regular expression, so `/files/{name}.json` also matched `/files/aXjson`. To use a regular expression in the `path` of an `api`, set `isRegExp: true`, which was ignored for paths with a template before [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A regular expression in the `path` of an `api` (`isRegExp: true`) is now matched against the request path as it is, without the query. Before, a slash was appended to both the expression and the path, so an expression anchored with `$` like `^/foo$` never matched, and a trailing slash was ignored. Now `^/foo$` matches `/foo` but not `/foo/`; write `^/foo/?$` to accept both. Paths without `isRegExp` still ignore a trailing slash [#3621](https://github.com/membrane/api-gateway/issues/3621)
- A `+` in a path parameter value is no longer decoded to a space: `/users/a+b` gives `a+b`. A space is sent as `%20` in a path [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A path parameter value must not contain an unescaped `#`, as required by OpenAPI. `/items/a#b` no longer matches `/items/{id}`, so OpenAPI validation answers `404`. `%23` is still decoded to `#` [#3517](https://github.com/membrane/api-gateway/pull/3517)
- Invalid URI templates are now a configuration error at startup instead of failing on every request: a curly brace outside a template expression like `/a/{b}}`, a parameter that occurs more than once like `/{id}/{id}`, and OpenAPI paths that differ only in parameter names like `/pets/{id}` and `/pets/{petId}`, which OpenAPI forbids but generated OpenAPIs often contain. The error stops the whole gateway from starting, not only the affected API, so a configuration that ran on 7.7 may not start after the update. The log shows `Paths ... of OpenAPI ... are identical, they differ only in parameter names.` or `Cannot use path ... as URI template`. To fix it, use the same parameter names in equivalent paths or merge them, and remove stray braces and duplicate parameters. For an OpenAPI the check only applies when requests or responses are validated, so as a stopgap you can turn off validation for that OpenAPI with `validateRequests: no` and `validateResponses: no`, or by removing `x-membrane-validation` from the document [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A request whose path contains an encoded `;`, `/` or `\` (`%3B`, `%2F`, `%5C`) is now rejected with `400 Bad Request` if decoding these characters would select another API, another OpenAPI document of the same API, or, if requests or responses are validated, another path of the OpenAPI document. For example, `/api%3Bx=1/admin` is rejected when there is an API for `/api/admin`, and `/api/public/x%2F..%2F..%2Fadmin` when the OpenAPI has the paths `/public/{file}` and `/admin`. A path where decoding does not change the selection, like `/projects/group%2Fproject`, is forwarded unchanged as before [#3545](https://github.com/membrane/api-gateway/pull/3545)
- A request with an absolute-form request target like `GET http://a.example.com/orders` is now routed by the host of the request target instead of the `Host` header, as required by RFC 9112 (section 3.2.2). The `Host` header is replaced with the host and port of the request target, so the flow (`${header.host}`, `X-Forwarded-Host`) and backends with `adjustHostHeader: false` see the same host that was used for routing. Before, `GET http://a.example.com/orders` with `Host: b.example.com` was routed to the API for `b.example.com`. Only clients that send an absolute-form target together with a different `Host` are affected; the forward proxy (`proxy`) still passes on the `Host` header it received [#3549](https://github.com/membrane/api-gateway/pull/3549)

### OpenAPI
- OpenAPI validation: a property not allowed by `additionalProperties: false` or `unevaluatedProperties: false` is now reported at the property, with one error per property, e.g. `REQUEST/BODY#/color`: `The property color is not allowed. The object does not allow additional properties.` Before, OpenAPI 3.0 and `unevaluatedProperties` reported one error at the object (`REQUEST/BODY`) listing all such properties, while OpenAPI 3.1 and 3.2 reported `The schema is false and does not allow any value.`. Clients that read the error location or message have to be adapted. In a response, these errors now carry status `500` like other response errors, instead of `400` [#3567](https://github.com/membrane/api-gateway/pull/3567)
- OpenAPI 3.1 and 3.2 validation: a `patternProperties` regex now matches anywhere in a property name, as JSON Schema requires, and is no longer anchored at both ends. With `"^x-": {type: string}`, the property `x-trace` now matches the pattern: its value is validated as a string, and `additionalProperties` no longer applies to it. Before, the regex had to match the whole name, so `x-trace` counted as an additional property. A request or response that passed before can now be rejected, and the other way round. To keep matching whole names, anchor the pattern with `^` and `$` [#3473](https://github.com/membrane/api-gateway/pull/3473)

### WSDL and SOAP
- WSDL validation (`validator` with `wsdl`, and `validator` inside a `soapProxy`) now checks the structure of the SOAP envelope as SOAP 1.1 and 1.2 require it, and rejects a message whose `Header` comes after the `Body` (`The SOAP Header must come before the Body.`), that has more than one `Header` (`The SOAP Envelope must not contain more than one Header.`) or more than one `Body` (`The SOAP Envelope must not contain more than one Body.`), whose `Header` or `Body` is not in the namespace of the `Envelope` (`The SOAP Body must be in the namespace of the Envelope, ….`), that has, in SOAP 1.2, an element after the `Body` (`A SOAP 1.2 Envelope must not contain an element after the Body.`), that has a header block without a namespace (`A SOAP header block must be namespace-qualified.`), or whose `Body` holds a `Fault` next to other elements (`A SOAP Body with a Fault must not contain any other element.`). SOAP 1.1 still allows elements after the `Body`. Before, such a message was passed on. A body element named `Fault` is only taken as a SOAP fault if it is in the namespace of the `Envelope` or unqualified; one in another namespace is now validated like any other body element, also with `skipFaults: true` [#3582](https://github.com/membrane/api-gateway/pull/3582)

### XPath, JSONPath, SpEL and Groovy
- More than one global `xmlConfig` in `components` is now a configuration error at startup as soon as a plugin uses `language: xpath` or `wsSecurity` is configured without its own `xmlConfig`. The log shows `One bean was asked. But found 2 beans of class com.predic8.membrane.core.config.xml.XmlConfig`. Before, this only failed for an `api` without its own `xmlConfig`, and on every request that evaluated a SpEL or Groovy expression or ran a `groovy` or `template` plugin, so configurations without such an `api`, for example with only `serviceProxy` or `soapProxy`, started. SpEL and Groovy expressions now only fail when they call `xpath()` in a plugin without its own `xmlConfig`. To fix it, merge the namespaces into one global `xmlConfig`, or reference the others with `$ref` from the plugins that need them [#3542](https://github.com/membrane/api-gateway/pull/3542)
- The `xpath()` function of SpEL and Groovy now uses the `xmlConfig` of its plugin, for example of `setHeader` or `if`, and the global `xmlConfig` only when the plugin has none. Before, it always used the global one, and the plugin's own `xmlConfig` was ignored. An expression like `${xpath('//o:id')}` in a plugin with its own `xmlConfig` no longer finds a prefix `o` that is declared only in the global one; declare it in the plugin's `xmlConfig` as well [#3542](https://github.com/membrane/api-gateway/pull/3542)
- XPath and JSONPath on the message body: the Content-Type now decides how the body is read. This applies to `if`, `choose`/`case`, the API `test`, `for`, `setHeader`, `setProperty`, the `keyExpression` of `rateLimiter` and `${...}` templates.
  - The body is parsed when its Content-Type is the language's own (XML for XPath, JSON for JSONPath), when it has no Content-Type, or when it is `text/plain`.
  - If such a body does not parse, a request is rejected with `400 Bad Request`, and a response from the backend is replaced with `502 Bad Gateway`.
  - Before, both languages answered with `500` for a body that did not parse. For XPath, the problem details of malformed XML or an empty body also carried a generic "Aborting!" detail and a stack trace; they now name the parser's message.
  - A broken expression still gives `500`. `setHeader`/`setProperty` with `failOnError: false` and `log` still only log the error. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- XPath on a message of another media type, for example `application/json`, or on an empty body, is now evaluated against an empty document.
  - The body is not parsed: `/a` is `false`, `not(/a)` is `true` and `string(/a)` is `""`.
  - Before, the body was parsed whatever its Content-Type. XML sent as `application/json` was evaluated, and JSON, text or an empty body failed with `500`.
  - XML sent as `text/plain` or without a Content-Type is still evaluated. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- JSONPath now parses a body that has no Content-Type or is `text/plain`.
  - Before, such a body counted as no JSON: a condition was `false`, and a value was `""`.
  - A JSON body sent that way is now evaluated. A body that is not JSON is rejected with `400`, or with `502` in the response. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- JSONPath on an empty body, or on a message of another media type, is now evaluated against an empty object.
  - The result is the same as for a JSON document without the queried field: a missing field gives `null` instead of `""`.
  - For example, `setHeader` with `${$.a}` on a `GET` request without a body no longer sets an empty value. [#3450](https://github.com/membrane/api-gateway/issues/3450)

### Plugins
- `rewriter`: a target URL with a path, like `url: http://backend.example.com/api/orders`, is now used as it is. The `rewriter` no longer rewrites the destination, so a mapping that matched the path of the target URL has no effect anymore. Rewrite the path in the target URL itself instead. Redirects (`redirect-temporary`, `redirect-permanent`) are now decided on the path and query of the request, not on the destination. A redirect rule now also applies to an API whose target URL has a path, where it was matched against the destination before and often did not apply, and the `Location` header no longer contains the path of the target URL [#3535](https://github.com/membrane/api-gateway/pull/3535)
- A target URL that cannot be parsed is now a configuration error at startup (`Invalid target URL: ...`). Before, it failed only when a request was forwarded [#3535](https://github.com/membrane/api-gateway/pull/3535)
- `rateLimiter`: a body that does not parse for a `keyExpression` in XPath or JSONPath is now rejected with `400`. Before, the request was counted under the shared key `unknown`, so every client with such a body drew from one quota. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- `rateLimiter`: when the `keyExpression` fails or evaluates to an empty value, for example because a client omits the header it reads, the request is now counted by its client IP address, the same way as without a `keyExpression`. Before, all such requests shared the key `unknown`, so a single client could use up the quota of every other client without a key. [#3495](https://github.com/membrane/api-gateway/issues/3495)
- `APIsJSON` is replaced by the new `apisJson` plugin, which follows APIs.json 0.24. `baseUrl` replaces `rootDomain` and `url`; without it, URLs come from the `Host` header of the request. Configurations using `APIsJSON` have to be migrated [#3556](https://github.com/membrane/api-gateway/pull/3556)
- `xmlContentFilter` and `soapStackTraceFilter`: a body that cannot be parsed (not well-formed, not XML, or with a `DOCTYPE`) is now rejected with `400` in the request and `500` in the response. Before, it was forwarded unfiltered, see Security [#3520](https://github.com/membrane/api-gateway/pull/3520)

### Kafka and JMS
- `kafkaProducer` and `kafkaConsumer` fail at startup with a configuration error when the Membrane Kafka Extension is not on the classpath [#3519](https://github.com/membrane/api-gateway/pull/3519)

### Java API
- Java API (only relevant when Membrane is used as a library): `WebSocketFrame.tryRead` takes the maximum payload size as an additional parameter and throws the new `WebSocketFrameTooLargeException` for larger frames. `WebSocketFrameAssembler` rejects frames larger than 16 MiB unless another maximum is passed to its new constructor [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Java API (only relevant when Membrane is used as a library): `WebSocketConnection.onMessage` is now only called for text and binary messages; ping and close frames are handled by the connection. `WebSocketConnection.WEBSOCKET_CLOSED_POLL_INTERVAL_MILLISECONDS` is removed: a connection is released as soon as the client is gone, so the poll interval is no longer needed [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Java API (only relevant when Membrane is used as a library): `StreamPump.StreamPumpStats` instances no longer share one list of stream pumps. Each router has its own, so stopping one router no longer closes the connections of all routers in the JVM. Code that created its own `StreamPumpStats` to see the pumps of a router has to use `router.getStatistics().getStreamPumpStats()` [#3478](https://github.com/membrane/api-gateway/pull/3478)
- Java API (only relevant when Membrane is used as a library): the `Router` parameter is removed from `TemplateExchangeExpression.newInstance`, from the constructors of `XPathExchangeExpression` and `JsonpathExchangeExpression`, and from `Target.applyModifications`. `AbstractExchangeExpression` no longer has a `router` field; an expression that needs the router gets it from its interceptor [#3573](https://github.com/membrane/api-gateway/pull/3573)

## New Features

### OpenAPI
- OpenAPI 3.1 and 3.2 validation supports `unevaluatedProperties`. It applies to the properties that no `properties`, `patternProperties` or `additionalProperties` of the schema or its subschemas evaluate, including `allOf`, matching `anyOf`/`oneOf` branches, `if`/`then`/`else`, `dependentSchemas` and the schema a `discriminator` selects. OpenAPI 3.0 does not have this keyword, so it is still ignored there [#3473](https://github.com/membrane/api-gateway/pull/3473)
- OpenAPI 3.1 and 3.2 validation supports `prefixItems`; `items` then applies only to the items after the prefix, as in JSON Schema 2020-12 [#3574](https://github.com/membrane/api-gateway/pull/3574)

### Plugins
- `apisJson`: publish an APIs.json 0.24 catalog of the gateway's APIs, now including `serviceProxy` and `soapProxy`, with `info` (contact, created, modified), `tags` and tag rules to select the published APIs, `maintainers`, ETag/If-None-Match and `HEAD`. New tutorial `tutorials/discovery/10-APIs-JSON.yaml` [#3556](https://github.com/membrane/api-gateway/pull/3556)

### Kafka and JMS
- `kafkaProducer`: send the request body to a Kafka topic through the Membrane Kafka Extension [#3519](https://github.com/membrane/api-gateway/pull/3519)
- `kafkaConsumer`: consume messages from Kafka through the Membrane Kafka Extension [#3533](https://github.com/membrane/api-gateway/pull/3533)
- `jmsProducer`: send the request body to a JMS queue or topic through the Membrane JMS Extension; the broker is configured with `jmsConnection` [#3601](https://github.com/membrane/api-gateway/pull/3601)

## Improvements

### Routing and URI Templates
- Parameter names in URI templates may contain any character except `{` and `}`, as allowed by OpenAPI, e.g. `/items/{id/x}` or `/items/{id?x}`. Before, they failed [#3517](https://github.com/membrane/api-gateway/pull/3517)
- Performance: URI templates of OpenAPI paths and of `api` paths are compiled once at startup. Before, the regular expression was compiled again, and an exception thrown, for every path that did not match a request [#3517](https://github.com/membrane/api-gateway/pull/3517)

### OpenAPI
- OpenAPI validation matches concrete paths before templated ones, as required by OpenAPI, whatever their order in the document: `GET /pets/mine` is validated against `/pets/mine`, not against an earlier `/pets/{petId}`, and `DELETE /pets/mine` gets `405` if `/pets/mine` has no `delete`. If several templated paths match, the first one that has the method of the request is used; `405` only if none of them has it [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A `405` from OpenAPI validation has an `Allow` header with the methods of the matching path, as required by HTTP, e.g. `Allow: GET, PUT, POST` [#3517](https://github.com/membrane/api-gateway/pull/3517)
- OpenAPI publisher: `/api-docs/ui` without an id answers `No OpenAPI document id` instead of looking up the id `ui`, the query string is no longer part of the document id, and 404s point to the `/api-docs` overview [#3510](https://github.com/membrane/api-gateway/pull/3510) [#3591](https://github.com/membrane/api-gateway/pull/3591)
- OpenAPI: a path parameter declared in an operation but missing from the path template is now logged as a warning instead of failing every request with `500` [#3523](https://github.com/membrane/api-gateway/pull/3523)

### WSDL and SOAP
- WSDL validation (`validator` with `wsdl`, and `validator` inside a `soapProxy`) can now validate SOAP header blocks as well, not only the body, with the new `validator` attribute `headers`. `headers: bound` validates the header blocks bound with `soap:header` in the WSDL binding against the WSDL's schemas, for requests those on the input of any of the service's operations, for responses those on the output, and for faults those bound with `soap:headerfault`. `headers: declared` validates in addition every header block whose element is declared globally in the WSDL's schemas, including included and imported ones, also in faults; this is for WSDLs that define header elements in `<types>` without binding them. A message with an invalid header block is rejected. SOAP envelope attributes like `mustUnderstand` or `actor`/`role` on a header block are ignored, as is the `wsu:Id` WS-Security puts on a signed header block. Header blocks whose element none of the WSDL's schemas declares, like WS-Security or WS-Addressing, are passed on unvalidated; if the binding mentions one, a warning is logged at startup. The default `headers: none` validates no header blocks, as before. Membrane 8 is planned to change the default to `bound` [#3582](https://github.com/membrane/api-gateway/pull/3582)
- WSDL validation: with the new `validator` attribute `requireBoundHeaders: true`, a message must carry the header blocks the WSDL binding declares with `soap:header` for its operation, a request those on the operation's input, a response those on its output. A message missing one is rejected with `The SOAP header block {namespace}name required by the WSDL binding is missing.` The operation is found by the body element; if that belongs to several operations, e.g. of two ports, only the header blocks all of them declare are required. Faults need no header blocks. It works with every value of `headers`, also with `none`, so presence can be required without validating the header blocks. The default `false` requires no header blocks, as before [#3582](https://github.com/membrane/api-gateway/pull/3582)

### XPath, JSONPath, SpEL and Groovy
- XML namespaces declared in a global `xmlConfig` in `components` now apply to every plugin that uses `language: xpath`, such as `setHeader`, `setProperty`, `if` and `choose`, and to the XPath references of `wsSecurity`, as they already did for the `xpath()` function of SpEL and Groovy. Before, these plugins only knew the prefixes of their own `xmlConfig`, so the global namespaces had to be referenced with `$ref` in each one. A plugin with its own `xmlConfig` uses only that one, with `language: xpath` as well as in the `xpath()` function [#3542](https://github.com/membrane/api-gateway/pull/3542)
- Groovy: the built-in functions like `xpath()`, `jsonPath()`, `user()` and `hasScope()` can now be called without the `fn.` prefix in `language: groovy` expressions (`setHeader`, `setProperty`, `if`, `choose`, ...) and in the `groovy` plugin, as in Groovy templates and SpEL, e.g. `${xpath('//id')}`. Before, only `fn.xpath('//id')` worked there. `fn.` still works, and a method defined in the script takes precedence over a built-in function of the same name [#3559](https://github.com/membrane/api-gateway/issues/3559)
- Form data, which `curl -d` sends for any body:
  - A body with the Content-Type `application/x-www-form-urlencoded` that holds XML or JSON is evaluated by XPath or JSONPath.
  - A body that holds neither is evaluated against an empty document. An info log message then tells you to send the matching Content-Type. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- The API `test`: a request body that does not parse makes the API not match, as before, but is now logged at debug level instead of a warning per request. [#3450](https://github.com/membrane/api-gateway/issues/3450)
- `choose`: the problem details of an expression error now keep the specific error detail. The generic message moved into the title. [#3450](https://github.com/membrane/api-gateway/issues/3450)

### Configuration
- YAML configuration: a syntax error is now reported with the parser's message and the offending line. Before, every parse error was reported as a missing `---` separator [#3576](https://github.com/membrane/api-gateway/pull/3576)
- `membrane.schema.json` (editor support): required child elements are marked as required, numbers and booleans are accepted in free-form attributes like `callTimeout: 30000`, and an invalid plugin in a flow or an invalid component entry now reports one error instead of one per plugin [#3600](https://github.com/membrane/api-gateway/pull/3600) [#3603](https://github.com/membrane/api-gateway/pull/3603) [#3605](https://github.com/membrane/api-gateway/pull/3605) [#3608](https://github.com/membrane/api-gateway/pull/3608) [#3610](https://github.com/membrane/api-gateway/pull/3610)

### Error Handling and Logging
- Production mode keeps the client-facing details of rejections: `apiKey`, `cors`, `idempotency`, `jsonProtection`, `rateLimiter` and `rewriter` now tell the client why a request was rejected, while internal fields stay hidden. `rateLimiter` returns the retry time, limit and duration as top-level fields and a `Retry-After` header. 5xx titles in production show the reason phrase of the status (e.g. `Bad Gateway`) instead of always `Internal Server Error` [#3493](https://github.com/membrane/api-gateway/pull/3493)
- Request URIs are logged at `debug` instead of `info` in rejection and validation logs, and are kept out of error details [#3547](https://github.com/membrane/api-gateway/pull/3547) [#3596](https://github.com/membrane/api-gateway/pull/3596)
- XML parse problems are logged via SLF4J instead of being printed as `[Fatal Error]` to stderr [#3516](https://github.com/membrane/api-gateway/pull/3516)

### HTTP Transport and Runtime
- Shutdown and hot deploy check for running exchanges every second instead of every 5 seconds, so they no longer take at least 5 seconds [#3593](https://github.com/membrane/api-gateway/pull/3593)
- Docker image: runs under `tini`, so the container stops cleanly and JVM shutdown hooks run on `docker stop` [#3505](https://github.com/membrane/api-gateway/pull/3505)

### Tutorials and Documentation
- Tutorials: new tutorials for routing, WebSockets, outgoing calls through an HTTP proxy, reusable plugin chains, basic authentication and OpenAPI, migrated from the examples; `curl` calls work on Windows as well as Linux/macOS and send a `Content-Type` with a body [#3435](https://github.com/membrane/api-gateway/pull/3435) [#3478](https://github.com/membrane/api-gateway/pull/3478) [#3525](https://github.com/membrane/api-gateway/pull/3525) [#3552](https://github.com/membrane/api-gateway/pull/3552) [#3431](https://github.com/membrane/api-gateway/pull/3431) [#3563](https://github.com/membrane/api-gateway/pull/3563) [#3528](https://github.com/membrane/api-gateway/pull/3528) [#3509](https://github.com/membrane/api-gateway/pull/3509) [#3502](https://github.com/membrane/api-gateway/pull/3502)

## Fixes

### Routing and URI Templates
- `Host` headers with bracketed IPv6 literals such as `[::1]:2000` now match [#3566](https://github.com/membrane/api-gateway/pull/3566)
- a forward proxy (`proxy`) bound to an IP address was never selected [#3464](https://github.com/membrane/api-gateway/pull/3464)
- adding, removing or replacing proxies at runtime no longer causes a `ConcurrentModificationException` for concurrent requests [#3463](https://github.com/membrane/api-gateway/pull/3463)

### OpenAPI
- OpenAPI: an API with several OpenAPI documents whose server paths are nested, like `/api` and `/api/admin`, now validates a request against the document with the longest matching server path. Before, the first matching document in the configuration was used, so `/api/admin/users` could be validated against the document for `/api` [#3545](https://github.com/membrane/api-gateway/pull/3545)
- OpenAPI validation and the `/api-doc` pages now use the same path as routing, without path parameters and with duplicate slashes merged. Requests like `/shop//products` or `/customers/7;jsessionid=1` were routed to the API but then answered with `404` or `400`. The `path` in the problem details of a validation error is now this path as well [#3545](https://github.com/membrane/api-gateway/pull/3545)
- OpenAPI 3.1 and 3.2: boolean schemas are enforced. `false` (e.g. `properties: {secret: false}`, `items: false`) now rejects every value; before, it accepted everything [#3500](https://github.com/membrane/api-gateway/pull/3500)
- OpenAPI validation: `enum` and `const` are checked for every type, not only strings, and a schema without `type` accepts all its enum members [#3592](https://github.com/membrane/api-gateway/pull/3592)
- OpenAPI validation: a JSON or XML media type without `schema` accepts any content instead of failing with `500` [#3571](https://github.com/membrane/api-gateway/pull/3571)
- OpenAPI validation: property names containing `/` or `~` are escaped in the JSON Pointer of an error (RFC 6901) [#3594](https://github.com/membrane/api-gateway/pull/3594)
- OpenAPI: `patternProperties` of exploded object query parameters are matched anywhere in the name, as JSON Schema requires [#3501](https://github.com/membrane/api-gateway/pull/3501)

### WSDL and SOAP
- WSDL validation: in a document-style operation whose message lists a header part before the body part, the header element was taken as the body element, so valid requests were rejected [#3582](https://github.com/membrane/api-gateway/pull/3582)
- WSDL validation: with several schemas embedded in the WSDL, an invalid message is now reported only with the errors of the schema that declares its element. Before, every other schema added `cvc-elt.1.a: Cannot find the declaration of element ...` to the error list [#3582](https://github.com/membrane/api-gateway/pull/3582)

### Plugins
- `accessLog`: an `additionalVariable` whose expression evaluates to nothing, such as `headers['traceparent']` for a request without that header, is now logged as its `defaultValue` (`-` unless configured). Before, it was logged as `null`. The same applies to the built-in values like `host` and `port` [#3583](https://github.com/membrane/api-gateway/pull/3583)
- `setHeader`/`setProperty` and the `keyExpression` of `rateLimiter`: a request body that cannot be read is now answered with `400`, as in `if` and `choose`, with the problem type `user/body-decoding` if its `Content-Encoding` could not be decoded. Before, `setHeader`/`setProperty` answered with `500`, and `rateLimiter` counted the request by its client IP address. `setHeader`/`setProperty` with `failOnError: false` still only log the error [#3462](https://github.com/membrane/api-gateway/issues/3462)
- `rewriter`: a target URL template with a base path, like `http://backend/api/${header.tenant}`, no longer answers every request with `400` [#3512](https://github.com/membrane/api-gateway/pull/3512)
- `idempotency`: concurrent requests with the same key could all pass; the key is now checked and marked atomically [#3514](https://github.com/membrane/api-gateway/pull/3514)
- `shadowing`: requests whose body was already read by an earlier plugin are now shadowed too [#3579](https://github.com/membrane/api-gateway/pull/3579)
- `webServer`: a request for a directory serves the configured index file again [#3474](https://github.com/membrane/api-gateway/pull/3474)

### Configuration
- YAML: a child element given through `$ref` satisfies a required child [#3598](https://github.com/membrane/api-gateway/pull/3598)

### HTTP Transport and Runtime
- A close-delimited backend response (no `Content-Length`, no chunking) is no longer treated as keep-alive [#3423](https://github.com/membrane/api-gateway/pull/3423)
- HTTP client: fixes for connection pooling and shutdown, HTTP/2 stream and shutdown races, and a `StackOverflowError` when closing a connection after pool shutdown [#3424](https://github.com/membrane/api-gateway/pull/3424) [#3541](https://github.com/membrane/api-gateway/pull/3541) [#3550](https://github.com/membrane/api-gateway/pull/3550)
- Thread and resource leaks: "Connection Closer" timer threads leaked by schema resolution, and files loaded via `location` (e.g. keys and certificates) were not closed [#3503](https://github.com/membrane/api-gateway/pull/3503) [#3508](https://github.com/membrane/api-gateway/pull/3508)
- A `CONNECT` rejected by an upstream proxy is answered with a `502` that respects production mode [#3507](https://github.com/membrane/api-gateway/pull/3507)

## Security
- XML bodies are parsed with the hardened parser in `xmlContentFilter`, `soapStackTraceFilter` and two more places that resolved external entities in a `DOCTYPE` (file read / SSRF). A body with a `DOCTYPE` could also slip unfiltered through `xmlContentFilter` [#3520](https://github.com/membrane/api-gateway/pull/3520)
- Upgrade BouncyCastle to 1.86 [#3470](https://github.com/membrane/api-gateway/pull/3470)
