# 7.8.0

## Breaking Changes
- WebSocket message size limit: when the `webSocket` plugin has frame interceptors (`wsLog`, `wsStompReassembler`, `wsInterceptor`), a message may now be at most 16 MiB, configurable with the new `maxMessageSize` attribute. A peer that sends a larger message, or announces a larger frame, is sent a close frame with status `1009` (message too big) and the connection is closed. Before, frames of any size were accepted and held in memory, so a single client could exhaust the gateway's memory. Without frame interceptors there is no limit, see below [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- WebSocket connections through a `webSocket` plugin without frame interceptors are now relayed byte for byte, without parsing WebSocket frames. Before, every frame was parsed and written anew, which held each frame in memory and closed the connection on frames it could not parse, such as a close frame without a status code [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Fragmented WebSocket messages are now joined when the `webSocket` plugin has frame interceptors: the interceptors and the receiving peer get each message as a single frame. Ping and pong frames between the fragments are passed on right away; a close frame in the middle of a message drops the incomplete message. Before, each fragment went through the interceptors on its own, so `wsStompReassembler` failed on the first fragment, dropped it and passed the rest on, and the receiver closed the connection with a protocol error. A continuation frame without a message to continue, or a new message before the previous one is complete, now closes the connection with status `1002` (protocol error) [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- WebSocket extensions are no longer negotiated when the `webSocket` plugin has frame interceptors: the `Sec-WebSocket-Extensions` header is removed from the upgrade request, so messages are not compressed with `permessage-deflate`. Frame interceptors could not read compressed messages, and RFC 6455 (section 5.4) does not allow joining fragments once an extension is in use. Configurations that removed the header themselves, for example with a `groovy` plugin, no longer need to. Without frame interceptors, extensions are negotiated as before [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- A failing WebSocket frame interceptor now closes the connection: both peers are sent a close frame with status `1011` (internal error), and the failure is logged at `ERROR`. Before, the message was dropped, the failure was logged, and the connection stayed open, so messages could get lost without either peer noticing. This also applies to `wsStompReassembler` when a text message is not a valid STOMP frame [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- WebSocket frame interceptors are now initialized once, when the API starts. An interceptor that fails to initialize stops the start with a configuration error. Before, the interceptors were initialized again for each new connection, while other connections were using them, and a failure was only logged. Custom interceptors (`wsInterceptor`) that relied on `init` being called per connection have to keep per-connection state elsewhere [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Upgraded connections (WebSocket, `Upgrade: tcp`), `CONNECT` tunnels of a forward proxy (`proxy`) and connections of a `stompClient` no longer time out on the backend side: once a connection is upgraded, the read timeout of the HTTP client (`connection.soTimeout`) no longer applies. Before, a connection on which the backend sent nothing for that long was closed, while the client side never timed out [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Admin API WebSocket (`/ws` of `adminApi`): an upgrade request without a `Sec-WebSocket-Key` header is now rejected with `400 Bad Request`. Ping frames are answered with a pong, and a close frame is answered with a close frame, after which the server closes the connection. Before, an upgrade without a key was accepted, and ping and close frames were ignored [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Java API (only relevant when Membrane is used as a library): `WebSocketFrame.tryRead` takes the maximum payload size as an additional parameter and throws the new `WebSocketFrameTooLargeException` for larger frames. `WebSocketFrameAssembler` rejects frames larger than 16 MiB unless another maximum is passed to its new constructor [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Java API (only relevant when Membrane is used as a library): `WebSocketConnection.onMessage` is now only called for text and binary messages; ping and close frames are handled by the connection. `WebSocketConnection.WEBSOCKET_CLOSED_POLL_INTERVAL_MILLISECONDS` is removed: a connection is released as soon as the client is gone, so the poll interval is no longer needed [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- Java API (only relevant when Membrane is used as a library): `StreamPump.StreamPumpStats` instances no longer share one list of stream pumps. Each router has its own, so stopping one router no longer closes the connections of all routers in the JVM. Code that created its own `StreamPumpStats` to see the pumps of a router has to use `router.getStatistics().getStreamPumpStats()` [#TBD](https://github.com/membrane/api-gateway/pull/TBD)
- URI templates in OpenAPI paths and in the `path` of an `api` now match their fixed text as it is, as defined by OpenAPI path templating. Before, characters like `.`, `+`, `$`, `(`, `)` and `*` acted as regular expression, so `/files/{name}.json` also matched `/files/aXjson`. To use a regular expression in the `path` of an `api`, set `isRegExp: true`, which was ignored for paths with a template before [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A `+` in a path parameter value is no longer decoded to a space: `/users/a+b` gives `a+b`. A space is sent as `%20` in a path [#3517](https://github.com/membrane/api-gateway/pull/3517)
- A path parameter value must not contain an unescaped `#`, as required by OpenAPI. `/items/a#b` no longer matches `/items/{id}`, so OpenAPI validation answers `404`. `%23` is still decoded to `#` [#3517](https://github.com/membrane/api-gateway/pull/3517)
- Invalid URI templates are now a configuration error at startup instead of failing on every request: a curly brace outside a template expression like `/a/{b}}`, a parameter that occurs more than once like `/{id}/{id}`, and OpenAPI paths that differ only in parameter names like `/pets/{id}` and `/pets/{name}`, which OpenAPI forbids. For an OpenAPI this applies when requests or responses are validated [#3517](https://github.com/membrane/api-gateway/pull/3517)

## Improvements
- OpenAPI validation matches concrete paths before templated ones, as required by OpenAPI, whatever their order in the document: `GET /pets/mine` is validated against `/pets/mine`, not against an earlier `/pets/{petId}`. If several templated paths match, the first one that has the method of the request is used; `405` only if none of them has it [#3517](https://github.com/membrane/api-gateway/pull/3517)
- Parameter names in URI templates may contain any character except `{` and `}`, as allowed by OpenAPI, e.g. `/items/{id/x}` or `/items/{id?x}`. Before, they failed [#3517](https://github.com/membrane/api-gateway/pull/3517)
- Performance: URI templates of OpenAPI paths and of `api` paths are compiled once at startup. Before, the regular expression was compiled again, and an exception thrown, for every path that did not match a request [#3517](https://github.com/membrane/api-gateway/pull/3517)
